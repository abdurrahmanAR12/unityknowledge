# Learning Paths

This page turns the docs into practical learning routes.

## Path 1 — Beginner who wants to build games

### Goal
Understand Unity well enough to build small complete projects without feeling lost.

### Sequence
1. Start Here
2. Installation and Editor Setup
3. First Project and Project Settings
4. C# and Unity Scripting
5. Project Organization and Version Control
6. UI
7. Physics
8. Builds
9. Optimization basics

### Skill milestones
- can create and organize scenes/prefabs
- can write and fix simple scripts
- can understand console errors
- can make a playable prototype
- can build to at least one target platform

## Path 2 — Indie developer who wants production discipline

### Goal
Stop shipping prototype habits into a real project.

### Sequence
1. Workflow pages
2. Architecture page
3. Assets page
4. Optimization page
5. Builds page
6. Testing page
7. Troubleshooting pages

### Skill milestones
- project structure stays readable over time
- feature work has test scenes
- package sprawl is controlled
- performance regressions are caught earlier

## Path 3 — Technical artist / graphics-focused developer

### Read first
- Graphics
- Assets
- Optimization
- UI if you touch interface presentation

### Watch for
- shader cost
- texture import settings
- material explosion
- pipeline mismatch issues
- build size impact

## Path 4 — Programmer moving into architecture

### Read first
- Scripting
- Common Scripting Errors and Debugging
- Architecture
- Workflow
- Testing
- Optimization

### Core growth areas
- serialization rules
- assembly definitions
- ScriptableObjects
- decoupling systems
- preventing hot-path allocations
- debugging lifecycle and scene issues

## Path 5 — XR / AR developer

### Read first
- Installation and Editor Setup
- First Project and Project Settings
- XR page
- Optimization page
- Builds page

### Critical discipline
XR projects punish bad setup and late performance testing.
Validate package versions and device behavior early.

## Path 6 — Multiplayer developer

### Read first
- Multiplayer page
- Workflow page
- Builds page
- Testing page
- Optimization page

### Critical discipline
Networking is easier when the local single-player architecture is already clean.
Messy local state becomes messy network state.

## Best study method for any path

For each topic:

1. read the page
2. build one tiny proof scene
3. break it on purpose once
4. fix it
5. record the lesson in a note

That is how knowledge becomes reusable skill.
