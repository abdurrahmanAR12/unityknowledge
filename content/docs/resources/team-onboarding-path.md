# Team Onboarding Path

This page is for bringing a new developer into a Unity project without overwhelming them.

## Week 1 goals

A new teammate should understand:
- project Unity version and target platforms
- render pipeline
- folder structure
- main scenes
- how to run the project safely
- where docs live
- how to make and review a small change

## Recommended onboarding order

1. [Start Here](/docs/start-here)
2. [What to Read by Need](/docs/what-to-read-by-need)
3. project-specific README / setup notes
4. [Project Organization and Version Control](/docs/workflow/project-organization-and-version-control)
5. [Package Management, Version Upgrades, and Migrations](/docs/workflow/package-management-version-upgrades-and-migrations)
6. one guided test scene walkthrough
7. one safe starter task

## Onboarding checklist

- [ ] can open project successfully
- [ ] can run intended main scene/test scene
- [ ] understands branching/commit rules
- [ ] knows where persistent systems are defined
- [ ] knows where package decisions are documented
- [ ] knows how to profile a scene and read Console errors

## Best practice

New developers should not start by editing the most fragile shared scene.
Give them:
- a small feature folder
- a test scene
- one focused task

That prevents accidental chaos.
